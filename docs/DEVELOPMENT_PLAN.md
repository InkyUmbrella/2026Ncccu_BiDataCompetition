# 后续开发计划：以T4交付为约束改善AUROC

制定日期：2026-10-27。规则和当前状态见 [合规核查](COMPLIANCE_REVIEW.md)。[官网](https://www.ncccu.org.cn/index/Paper/case2.html?way=1)已确认区域赛/省赛截止为**2026-11-06 23:59（北京时间）**，评测为单张NVIDIA T4 16GB，Python 3.12 / PyTorch 2.10.0 / torchvision 0.25.0 / CUDA 12.8 / cuDNN 9，驱动≥570.117。按下述优先级和截止闸门安排，不承诺未经测量的耗时或分数。

目标：在合规、单图端到端≤100ms、实际部署文件≤500MB的候选中提高完整valid AUROC，并能交给队友在4090复现。**当前仅制定计划；下面的模块、配置和实验均不能当作已经实现或运行。**

## P0：先完成许可、统一推理和T4计时基础

这是第一个开发批次，优先于新增完整训练。

**拟交付：**

- 具体权重来源清单与许可/上游数据证据；固定原文件SHA256，明确是否可启用。不把模型家族名或源码许可证当作权重许可的替代证明。
- 共用的单图推理模块（建议`src/glaucoma/inference.py`）、正式`predict.py`及根目录`cost.py`；现有CLI迁移为调用共用实现，保留旧checkpoint兼容。
- 冻结的`inference_spec.json`：模型/权重哈希、图像尺寸、裁边、插值/补边、归一化、精度、TTA/集成、阈值和代码版本，避免预测与计时各写一套逻辑。
- 推理文件大小清单；不把未使用的训练断点或官方初始化文件算成必然要加载的推理模型。
- 单独的官方评测环境兼容性记录：核验官网推荐镜像及digest或记录等效环境；保留原服务器已测依赖，不原地升级。检查旧checkpoint在Python 3.12/PyTorch 2.10.0下加载、FP16推理及CSV一致性。
- 落实官方数据记录的访问范围。公开仓库现含验证图片名/标签，先处理可见性或完整历史清理方案；新逐样本材料放内部服务器归档，公开Git只放代码、汇总和哈希索引。

**验收：**

1. 模型加载不联网；使用eval与inference_mode；同图不受前后测试样本影响，随机训练增强完全关闭。
2. 开发阶段用合成图片及固定train/valid工程样本检查重复推理/计时；不以test预测分布指导开发。
3. 计时从读原图开始，到最终结果写出并flush结束；CUDA同步，batch1串行，不预先缓存100张解码结果或预测绕过I/O。
4. `cost.py`按100张×3轮、5张预热执行，与同一spec的CSV逐张比对；最终报告平均耗时、精度、大小和不一致数，结果需一致。旧batch32生成的CSV不能直接充当batch1一致性的证明。
5. 先用该统一单图FP16路径重算refine完整valid，保存与历史batch32结果的差异表。历史0.9873283254保持原记录；新候选统一相对于这次复核基准比较，避免混用批次/精度口径。
6. T4实机才能确认100ms要求。服务器V100只验证工程、队友4090只承担训练和工程检查；T4不可用时标记性能待测，不宣称达标。工程余量目标80ms不是赛事硬性新增要求。
7. 按8核CPU、32GB内存和SSD条件核对交付环境；官方软件版本下也需工程检查。若共享服务器驱动不满足新容器要求，记录阻碍并在适配机器验证，不擅自升级共享服务器驱动。既有环境通过不代表指定环境通过。

若基准单模型已超时，先分解读图/预处理/前向/写出耗时，优化确定性实现；精度或导出方式变更后在valid重新核验。暂不叠加TTA和多模型。

## P1：不增加训练轮数的有限验证

只登记两个当前refine候选：**原单图**、**原图+水平翻转双视图**。在相同完整valid、同精度下比较AUROC/AP/PR梯形面积、预测顺序及耗时。

双视图按两个sigmoid概率等权平均，变换和权重事前固定；不做随机TTA或大量角度/裁剪组合搜索。指标不提高则保留原单图；T4总耗时超过100ms则不作为最终候选。规则允许不代表一定有收益。

## P2：第一项正式新配方——512分辨率微调

提高细节保留量是待验证假设，不保证优于384。先做512形状的工程/显存/耗时检查，再交4090完整训练。

| 参数 | 预定值 |
|---|---|
| 模型 | 现有ConvNeXt-Tiny纯图像 |
| 初始化 | 固定旧B0第5轮best，SHA256 `c9a7c3c6cf7802b96d43bc7e89737579d43324ccd4b1afdfb76ec5fe2978bb18` |
| 数据 | 官方train/valid保持分开，512裁黑边/等比补边、ImageNet归一化 |
| 轮数/seed | 独立10轮，seed42 |
| 优化 | 沿用refine：最高LR1e-5、最低1e-7、1轮warmup、AdamW、wd0.05、pos_weight5、EMA0.999 |
| batch | 优先32×累积4；若实际显存不足，事前确定16×8，保持有效128并记录差异 |
| 选模 | 每轮完整valid raw/EMA；按AUROC、并列PR梯形面积，保留普通best.pt |

与已完成384 refine使用同一固定初始化及主要配方比较；若microbatch改变，不宣称是严格单因素因果消融。512无损缓存必须另建，不能套用384缓存；允许直接读原图，缓存只是I/O选项。

拟新增配置名`b0_crop512_refine_ema.json`。它目前不是已存在可运行的命令。若T4单次前向就无法满足预算，优先停止这条交付路线，而非再加多裁剪救分。

## P3：第二项新配方——通用DINOv2小骨干

限定**原始通用`dinov2_vits14`**，不使用同仓库XRay/Cell等医学变体。官方model card列出Apache-2.0、LVD-142M、21M参数及patch14，见 [官方model card](https://github.com/facebookresearch/dinov2/blob/main/MODEL_CARD.md)、[许可说明](https://github.com/facebookresearch/dinov2#license)及 [数据来源论文](https://arxiv.org/html/2304.07193v2#S3)。这是上游通用预训练；本项目只做赛方标签的监督微调，不进行医学自监督续训。

官方通用[权重直链](https://dl.fbaipublicfiles.com/dinov2/dinov2_vits14/dinov2_vits14_pretrain.pth)本次无登录HEAD检查为200、88,283,115字节。尚未下载该文件核算SHA256，**不能将其记成已经接入/完整核验的初始化**。正式接入须固定上游代码commit、精确权重、许可文本及哈希。

| 参数 | 预定值 |
|---|---|
| 输入 | 392×392（14的整数倍），原有确定性裁边/等比补边、ImageNet归一化 |
| 分类头 | CLS特征→128维头→单logit，不加入年龄或外部定位模型 |
| 轮数/seed | 独立15轮，seed42 |
| LR | 分类头最高1e-4、骨干1e-5；最低头LR1e-6、骨干相应倍率0.1 |
| 其余 | 1轮warmup，AdamW/wd0.05/pos_weight5/EMA0.999，micro16×累积8=128，FP16 |

这是一项新骨干/预训练配方比较，不宣称隔离了架构、数据和超参数的各自贡献。

**工程范围：** 扩展模型注册与初始化来源校验，统一记录权重URL/许可/数据/哈希；审计模块目前按ConvNeXt枚举查预训练源，必须同步扩展。推理须离线构造架构，不在评测时通过未固定版本的Torch Hub下载代码/权重；不能依赖只在较新GPU上可用的自定义注意力算子。保留旧ConvNeXt配置和checkpoint行为，验证初始化、FP16、EMA、完整resume、普通best推理和T4运行。

若原始通用权重的许可/来源不能闭环，或T4预算不合适，则停止这条路线。ConvNeXt V2官方NC权重不作为替补，依据 [官方许可说明](https://github.com/facebookresearch/ConvNeXt-V2#license)。

## P4：一次确认与一次有条件的固定集成

- 只有新增正式配方出现正收益时，才重复其中较好的一个，seed43，参数/初始化来源保持一致。小增益保留报告，优先为较明确的提升（例如≥0.0005）投入复核；该数值只是资源排序标准，不是官方门槛或显著性证明。
- 对512路线而言，seed43仍继承同一旧B0初始化，仅检验微调阶段随机性；不能称作整个训练流程的独立多seed重训。
- 仅当新模型具备互补证据且T4预算有余量，试**一次**“当前refine+最佳新模型”的等权概率平均。没有收益就回退单模型，不扫描大量融合权重，也不自动展开TTA×集成的笛卡尔积。
- 采用完整valid的同序配对分层bootstrap（1000次，seed20261023），同时列AUROC/AP/PR、差值和区间；区间不能消除反复选模偏差。患者分组信息未知时不把图像bootstrap称作患者级证明。

## 本批预算与停止条件

**正式训练最多2个新配方+1次确认；最多3次运行、合计不超过40个新增epoch。** 只有512和DINO两项都进入完整训练且DINO被选中再复核15轮时才到40；只执行可行项目，不为填卡启动实验。

**截止闸门（内部目标，不是官方新增期限）：** 10-27至10-29优先P0与访问范围处理；10-30至11-03仅安排通过工程检查、且队友4090预计能完成的P1–P3；11-04只做来得及的确认及T4验收，不新增配方；11-05冻结候选、整理复现材料；11-06 21:00前完成最终核验并交用户操作平台，留出到23:59的缓冲。环境或训练进度不足时删减P2–P4，不压缩材料/性能核验；40轮是上限，不是必须跑满。未通过许可或T4要求的候选不能因临近截止自动视作合格。

两项都未提升，就保留现有refine，停止本批；不自动重启旧30/20/10/15轮任务。任何超出本批的损失函数、更多架构、ROI或大规模超参数搜索，重新形成独立计划和预算。遇到实际错误先最小诊断并保留证据，恢复用该运行完整last，不用best代替；不因故障悄悄增加完成轮数。

单模型阈值改变或严格单调的概率校准不会改变排序型AUROC，不作为首批提分项目。也不优先做外部医学定位/分割、测试自适应、医学自监督、NC权重或无法装入体积/耗时预算的大模型。

## valid合并训练：允许，但不纳入本批默认安排

探索阶段保持官方划分。若以后选择train+valid做最终训练，必须事先冻结模型、初始化、超参数、轮数、raw/EMA选择、精度、TTA/融合和阈值，另写不再读取valid选模的final-fit入口。**不能只合并数据再沿用当前trainer的valid评估/挑best逻辑。** 不把合并后在原valid上得到的指标当泛化成绩，不用test决定何时停止。该独立阶段不自动追加在本批40轮预算之后。
