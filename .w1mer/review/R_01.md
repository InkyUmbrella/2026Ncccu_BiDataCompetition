## 3. Is `valid AUROC ~0.93` trustworthy? How many seeds?

**As a point estimate for one model, plausible but untraceable; as a model-selection
signal, no.**

- The only committed evidence is 0.886 (B0, 60 ep) and 0.878 (B1); 0.93 has no
  artifact in the repo (F1). First reproduce it and archive the run.
- Marginal uncertainty: with `n1=191`, `n0=5658`, `A=0.93`, Hanley–McNeil gives
  `SE(AUROC) ≈ 0.0129` → **95% CI ≈ ±0.025**. The 191 positives dominate.
- Selection over ~60 correlated checkpoints on the same valid set adds roughly
  **+0.5-1.0 SE of optimism** (≈ +0.006-0.013). So even 0.93 is likely
  ~0.005-0.01 high relative to an unseen split.
- Paired difference: if two models' image-level scores correlate ρ≈0.90-0.95,
  `SE(ΔAUC) ≈ SE·sqrt(2(1-ρ)) ≈ 0.004-0.006`. **A +0.003 delta is 0.5-0.75
  paired SE — not resolvable** (two-sided p≈0.3-0.6).
- **Rule I would enforce:** do not believe any delta < 0.005 from one seed.
  Minimum protocol for a go/no-go: **3 seeds** with the same split, report
  mean±range and a **paired bootstrap over the 5,849 images (≥5000 resamples)**
  of `ΔAUROC`; require the 95% CI lower bound > 0 **and** agreement in sign across
  seeds. To claim +0.003 specifically: **5 seeds** plus paired bootstrap is the
  practical minimum, and even then it is ~1σ of the seed mean — treat it as
  inconclusive unless confirmed on a held-out half or the leaderboard. AUPRC with
  191 positives is noisier still: don't gate on `ΔAUPRC < 0.01`.
- No patient ID exists: the bootstrap is eye-level, so CIs are **too narrow**;
  same-patient eyes can straddle train/valid. State this wherever a CI is quoted.
- Consequence for the queue: the 384-control vs 384-sampled and 384 vs 512
  comparisons (tasks 05/06) need the seed/paired protocol above, otherwise the
  winner will be picked by selection noise.

## 5. Verified correct (do not re-audit)

- **Accumulation / short window:** `train_one_epoch` computes
  `window_samples = min(accum*bs, N-seen)` at each window start and
  `backward(loss_sum/window_samples)`; `seen` advances by the true batch size, so
  the last partial window is normalised by its own sample count. That is exactly
  the full-batch mean; `tests/test_baseline.py:149-178` checks 7 samples/accum=3
  against a full batch elementwise. `pos_weight` is applied per sample inside the
  sum, so accumulation does not distort it.
- **LR:** `updates = ceil(ceil(N/bs)/accum)`, `total_steps = updates*epochs`,
  `warmup_steps = updates*warmup_epochs`; `learning_rate(step)` = linear
  `(step+1)/warmup` then cosine to `min_lr` at `step=total_steps-1`; test asserts
  the three endpoints. `global_step` is restored on resume. Skips do not advance
  it (F11, benign unless skips are frequent).
- **Best/last:** `score = (auroc, auprc_trapz)` with strict `>` keeps the earliest
  on exact ties; `auroc` cannot be `None` because both labels are enforced in
  valid (trainer.py:71-74). `best.pt` is `kind="inference"` (+metrics); `last.pt`
  is `kind="training"` (+optimizer/scaler/RNG/history/best). Final `metrics.json`
  re-evaluates the loaded best weights, so it matches the selected epoch.
- **Resume:** config equality except `data.root`/`output_root`, CSV sha256 check,
  model/optimizer/scaler/RNG/history/best restore; `new_run_directory` per
  invocation; `tests/test_baseline.py:200-239` and
  `test_age_residual.py:197-224` verify bit-exact weights after a stop/resume
  (CPU, workers=0).
- **Loaders/seeding:** train loader is rebuilt per epoch with
  `seed+epoch`; `WeightedRandomSampler` uses the same generator; `seed_worker`
  seeds Python/NumPy from `torch.initial_seed()` and torch is seeded by the
  DataLoader itself; both paths are deterministic and resume-stable.
- **Crop/letterbox:** scale by `size/max(W,H)`, aspect preserved, centred black
  pad, `min/max` clamps, 10% area guard against bright specks; EXIF transpose +
  RGB before everything; cache stores the post-letterbox uint8 tensor so
  ToTensor is bit-identical (`tests` assert atol=rtol=0 for train and eval
  transforms); `ImageCache` rejects size/preprocessing/CSV/stat mismatches.
- **Age:** stats fitted on train valid ages only (0,100]; missing→median+flag,
  invalid→median+flag; `is_missing` and `is_invalid` are mutually exclusive;
  stats live in the checkpoint and are reused at inference (no train/test skew).
- **Eval/submission:** metrics use fp32 `sigmoid` probabilities (logits only for
  ranking value and loss); AUROC/AP/trapz are kept separate; `roc_curve` sens@spec95
  picks max TPR over FPR≤0.05; CSV order and original names are preserved via
  `read_samples`; empty/duplicate/missing/case-ambiguous names raise; output files
  are created exclusively (`"x"`).
- **Configs in this batch:** `b0_crop384_control`, `b0_crop384_sampled` and
  `b0_crop512_sampled` all pass `Config.validate`. 384: 804 batches/2 = 402
  updates/epoch, effective batch 128; 512: 1607 batches/4 = 402 updates/epoch,
  effective batch 128 — so the step-based LR schedule is identical and resolution
  is the only delta. **But** the pre-existing B0/B1 runs are **crop=False,
  pos_weight=5, B0/B1**; the new control is **crop=True**, so do **not** attribute
  new-vs-old differences to sampling/resolution (and B1 uses age concat, a
  different model).

## 6. Architecture-impact note (for `.w1mer/codebase/`)

`train()` is the single entry: resume contract = config equality (root/output
excepted) + CSV sha256 + optimizer/scaler/RNG/history + `best`; `best.pt` is
inference-only (config+age_stats+weights+metrics), `last.pt` recovery-only. Data
contracts: CSV order/name (casefolded match, duplicates rejected) and cache
identity = preprocessing spec + image_size + CSV sha256 + per-file size/mtime.
Preprocessing code/version is **not** in checkpoints. Configs extend the 384/512
grid at a constant 402 updates/epoch and effective batch 128.
