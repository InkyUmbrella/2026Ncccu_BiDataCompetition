## 1. Verdict

**The EMA, Mixup/CutMix, label-smoothing and stochastic-depth implementations are
mathematically sound and the four planned arms will not be corrupted by them.**
EMA is an fp32 shadow of every floating state entry, updated once per *real*
optimizer step under the same condition that advances `global_step`, used for
validation/best-selection/`best.pt`, and exactly restored on resume (RNG included).
Mixup/CutMix mix image and target with the same lambda, CutMix re-derives lambda
from the *clipped* box area, the loss normalisation of a short final window is
exact, and label smoothing composes linearly with mixing (no double smoothing).

**But the "default-off = no behaviour change" claim is false for the ConvNeXt
model.** torchvision `convnext_tiny` defaults `stochastic_depth_prob=0.1`; the old
code called it with no argument, the new code passes `0.0` when the key is absent.
Every existing config/checkpoint therefore silently loses stochastic depth on
resume/re-run, and the default training path (and its RNG stream) is *not*
bit-identical to the previous version. The test that claims to prove parity uses
`LinearClassifier`, so it cannot see this. This does not corrupt the four fresh
arms internally, but it invalidates comparisons with historical baselines and the
FEATURE.md conclusion "none for default runs".

## 3. Answers to the explicit review questions

### 3.1 EMA

| Question | Finding |
|---|---|
| fp32 shadow covering every float param/buffer? | **Yes.** `ModelEMA.__init__` (`ema.py:23-25`) takes `model.state_dict()`, keeps floating entries, casts to fp32. ConvNeXt-Tiny has no BatchNorm/running buffers; its LayerNorm weights/biases are parameters and are shadowed. Integer buffers (`num_batches_tracked` on BN models) are excluded from the average but preserved by `store/restore`. |
| Update formula and frequency | **Correct.** `shadow = d·shadow + (1−d)·live` (`ema.py:41-42`), after the optimizer step, only when `scaler.get_scale() >= previous_scale` (`optimization.py:110-118`) — exactly the same predicate that advances `global_step`. PyTorch `GradScaler` always halves the scale when `found_inf` is set, so a skipped step always yields `get_scale() < previous_scale`; growth-interval increases satisfy `>=`. |
| Warmup/bias formula | **Correct** for the timm/torchvision convention: `min(decay, (1+step)/(10+step))` with `step = num_updates` (0-based), used before increment. There is **no** `1−d^t` bias correction; with `ema_decay=0.999` and warmup 0 the first epoch's EMA is ~67 % random init (`0.999^402`, i.e. 402 steps/epoch at 51,396 train images, bs 64, accum 2). Late epochs are unaffected; do not read epoch-0/1 EMA metrics as model quality. |
| Does validation use EMA? | **Yes.** `trainer.py:147-153` wraps `collect_predictions` *and* `inference_payload` inside `apply_ema`; ConvNeXt has no BN buffers that would be stale. |
| Swap/restore exception-safe? | **Yes.** `store` clones the full `state_dict`; `copy_to`/`restore` are in `try/finally` (`ema.py:88-93`); `restore` uses `load_state_dict(..., strict=True)` and clears `_backup`. |
| `best.pt` guaranteed EMA? | **Yes when EMA is on**, because `inference_payload` is called inside the context; on resume, the saved `best` payload is already an EMA snapshot and is rewritten unchanged. Test coverage is weak (F3), not the code. |
| `last.pt` resume exact? | **Yes.** `last.pt` is written after the `apply_ema` block, so `model_state` is the live model; the payload also stores `ema.shadow` + `num_updates` and the RNG state. `_resume_compatible` compares the full `to_dict()` (only `data.root`/`output_root` excepted), so changed EMA/sampling settings are rejected; a missing `ema` key raises. The committed test performs a 1-epoch + resume vs full-run bit-identical comparison of `model_state`, shadow and `num_updates` under mixup+smoothing+warmup. Pass. |

### 3.2 Mixup / CutMix

- Lambda: `lam ~ Beta(alpha, alpha)`; images and targets use the same lambda (`optimization.py:55-61`). CutMix computes `lam' = 1 − clipped_box_area/(W·H)` and mixes targets with `lam'` (`:64-74`) — correct, and the clipping is accounted for. When both are enabled, a 50/50 `torch.randint` choice is made first (`:51-54`).
- Determinism: all draws (`randint`, `Beta`, `randperm`) come from the global CPU RNG, which is seeded by `seed_everything` and restored by `restore_rng` at epoch boundaries; the committed resume test covers this. DataLoader shuffling/sampling uses its own per-epoch generator (`make_loader`), so it does not perturb the mixup stream.
- Loss normalisation: mixing is applied on every micro-batch (never skipped for the short final window) and `window_samples` is recomputed at each window start from `len(dataset) − seen`, which equals the *actual* number of samples in the window even when the final batch is short. No bias.
- `pos_weight`: see F2. With `pos_weight=1.0` (planned mixup arm) soft-target BCE is the standard mixup objective. With `pos_weight=5` it is still a valid loss but no longer equivalent to class reweighting of hard labels.
- Ages are not mixed (F9); irrelevant for `use_age=false`.

### 3.3 Label smoothing

- `smooth_labels` returns `y·(1−s) + 0.5·s` and returns the input object untouched at `s=0` (`optimization.py:29-33`). This is the correct BCE smoothing (targets in `[0.5s, 1−0.5s]`).
- Applied to hard labels **before** mixing. Because mixing is linear, `mix(smooth(y1), smooth(y2)) == smooth(mix(y1, y2))`: no double smoothing, and the mixed target range is `[0.025, 0.975]` for `s=0.05`.
- Interaction with `pos_weight` is the same F2 distortion (a smoothed negative has optimum `p ≈ 0.11` at `w=5`); not used in the planned smoothing arm (`pos_weight=1.0`).

### 3.4 Stochastic depth

- Plumbing is correct: `stochastic_depth_prob` is a `model.params` kwarg, passed to `convnext_tiny` (`convnext.py:18`) and forwarded by `ConvNeXtAgeResidual` (`:38-40`). Validation `[0,1]`, bool rejected.
- State dict: torchvision's `StochasticDepth` has no parameters/buffers; the committed test asserts identical keys/values for omitted / explicit `0.0` / `0.3` and identical eval outputs. Old ConvNeXt checkpoints load `strict=True`.
- **But** the default changed from 0.1 to 0.0 (F1). The old `R_01 F20` note ("the ConvNeXt used here has no stochastic depth") was wrong; the pre-02 code did train with torchvision's default 0.1.

### 3.5 Default-off no-op

- With all new keys unset: `ema=None` (not constructed), `smooth_labels(..., 0.0)` returns the same object, `mix_batch` takes the `not choices` path before any RNG draw, `apply_ema(None, model)` yields directly, and `last.pt` omits the `ema` key. So for the training loop there are no extra forward passes, no extra RNG draws and identical losses.
- The committed `test_defaults_preserve_original_math_and_rng` (LinearClassifier, dropout=0.2) does compare a hand-written pre-upgrade accumulation loop against `train_one_epoch` bit-for-bit including the post-loop CPU RNG state — it is meaningful for the *loop*, but **not** for the model: F1 means the ConvNeXt default path is not the old path. Net: claim only partially true.

### 3.6 Config compatibility / resume

- Old JSON configs load: the new `TrainConfig` fields have defaults; `from_dict` is strict only for *unknown* keys. `to_dict()` appends the new fields, so field order of existing keys is unchanged.
- Resume rejects changed EMA/sampling/smoothing/SD parameters via the existing full-dict comparison in `_resume_compatible`. It also rejects EMA-on over an EMA-less checkpoint. Old checkpoints resume as long as EMA stays off — but with F1's silent SD change (training-time only; weights load fine).
- `metrics.json` (final) loads `best["model_state"]`, which is the best-epoch EMA snapshot; there is no separate final-epoch EMA evaluation. Intentional, but word F7 accordingly.

## 4. Architecture / contract impact

- New module `engine/ema.py`; new `TrainConfig` fields (`ema_decay`, `ema_warmup_steps`,
  `mixup_alpha`, `cutmix_alpha`, `label_smoothing`); `train_one_epoch` gains an
  optional `ema` argument; `train()` wraps validation/best inside `apply_ema`;
  `last.pt` gains an `ema` section; `model.params` gains `stochastic_depth_prob`.
  No changes to `best.pt`/`metrics.json` schemas, inference API, data pipeline,
  optimizer grouping or LR schedule.
- Compatibility: old configs/checkpoints read; resume equality automatically covers
  the new keys. The only semantic migration is F1 (SD default 0.1 → 0.0).
